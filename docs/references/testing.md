# Testing

- Write synchronous tests for synchronous behavior. Mark tests that await
  asynchronous behavior with `@pytest.mark.anyio`; the shared
  `tests/conftest.py::anyio_backend` fixture selects asyncio.
- Run `uv run pytest` from the repository root, where `pytest.ini` selects
  `tests/` and adds `scripts/` to the import path.
- Reuse shared model helpers in `tests/conftest.py` for test data when they fit
  the scenario.
- Avoid asserting on logging in tests by default — logging is usually non-functional behavior. Exception: when log level itself is an explicit contract (for example, upstream status severity policy), assertions may verify level/metadata while avoiding brittle full-message matching.
- Construct SDK errors via the `tests/conftest.py` helpers — `make_sdk_status_error(status, msg, body=..., cls=<APIStatusError subclass, e.g. AuthenticationError>)` and `make_sdk_connection_error()` — not hand-built `httpx.Request`/`Response` + exception. Pass `body={"detail": ...}` when a test asserts on the surfaced message (the global handler reads `exc.body["detail"]`).
- When mocking SDK paginator calls used with `async for` (e.g., `client.faces.list`), use `Mock(return_value=MockSyncCursorPage([...]))` — not `AsyncMock`. `AsyncMock` wraps the return in a coroutine, which breaks `async for` iteration. Use `AsyncMock` only for calls consumed with `await`.
- The shared `MockSyncCursorPage` (`tests/conftest.py`) yields a flat list — it can't distinguish "limit is per-page" from "limit is a result cap" semantics. When testing code that explicitly `break`s out of `async for` after N items (e.g., `_fetch_assets_for_day`), use the shared `MockPaginatedListing` (`tests/conftest.py`), which tracks page boundaries so a regression that drops the break visibly walks extra pages. Its `page_size` must equal the `limit` the code actually sends — either read it off the call or pin it with a `call_args.kwargs["limit"] == page_size` assertion; a test-picked number with neither lets the two silently drift.
- Explicitly populate SDK attributes on `Mock` fixtures, including falsy
  values such as `metadata=None`. Unset attributes are truthy mocks: predicates
  such as `.startswith(...)` can silently take the wrong branch. Passing an
  unset field directly into a Pydantic DTO instead raises `ValidationError`.
  Whenever a field is renamed, added, newly tested by a predicate, or forwarded
  into a DTO, audit both shared helpers (`tests/conftest.py` and
  `tests/unit/api/sync/conftest.py`) and every inline entity mock in `tests/`.
  Give fixture helpers an explicit keyword with a realistic default; video
  URL fixtures must also specify a video MIME type. A converter-local test or
  a task's fixture list does not cover the full suite's mock constructions.
- A `Mock` satisfies any `typing.Protocol` structurally, so tests built on Mock fixtures give a Protocol **zero** conformance checking, and production call sites only cover the classes they actually pass. Pin it with an annotated list of the conforming classes (`STACK_ROW_CLASSES: list[type[GumnutStackRow]]` in `tests/unit/utils/test_stack_conversion.py`); pyright then rejects a class that drifts. Derive nothing from `Protocol.__protocol_attrs__` — it is a runtime-only CPython internal and pyright errors on it.
- A `Mock` also **fails** `isinstance(entity, <concrete SDK class>)`, so a branch behind such a guard is dead in a Mock-based test and the test can pass vacuously. The event-time payload overrides in `_stream_entity_type` (face `person_id`, album cover, asset `stack_id`) are gated on `isinstance(entity, AssetResponse/FaceResponse/...)`; hydrating the entity with `make_gumnut_asset()` (which returns a `Mock`) skips the override entirely — build a real SDK response to exercise it (see `tests/unit/api/sync/test_sync_stream_stacks.py::test_asset_uses_event_time_stack_membership`).
- The sync test helpers (`tests/unit/api/sync/conftest.py`) derive **every** entity ID (album, user, asset, person, face) from the same `TEST_UUID`. A test that asserts two distinct ID fields of one converter output (e.g. an album-user's `albumId` and `userId`, or a face's `assetId` and `personId`) both equal `TEST_UUID` can't detect a field swap between them — call the converter directly with a *distinct* value for the second ID so a swap fails. See `tests/unit/api/sync/test_sync_stream.py::test_album_user_converter_maps_album_and_owner_distinctly`.
- The same trap has three other shapes, all of which pass while pinning nothing. **Equal-by-fixture values**: if every fixture makes a source equal some other value in scope, swapping one for the other passes the suite — vary them in at least one test (`test_trashed_bucket_member_cannot_be_named_cover` is the only fixture where a stack row's `asset_count` and its resolved member count differ, so it carries that assertion). **Two paths that look like different rules**: before writing a test to pin the difference, trace both over the input each caller really passes — if they agree everywhere there, the divergence is in the *input*, not the rule, and a test feeding them different inputs pins neither. The timeline and `/stacks` covers read that way for a whole review round; they now share one function and differ only in which member set they run it over. **Assertions true by construction**: the bucket's columnar arrays are largely `[None] * asset_count`, so asserting their lengths match can never fail for those columns; pair a value to its own asset instead. In each case, check the test still fails when the defect it names is reintroduced.
- Tests that coordinate concurrent tasks/requests with `asyncio.Event` waits must bound the coordination with `asyncio.timeout(...)` — the repo has no pytest-timeout configured, so a regression in the ordering assumptions deadlocks the whole suite instead of failing one test. See `tests/unit/utils/test_token_refresh.py` for the pattern.
- Unit tests call endpoint handlers directly, bypassing FastAPI parameter resolution — a parameter declared `x: bool = Query(default=None)` receives the raw `Query` object (which is truthy), not `None`, so `if x:` silently takes the True branch. The fix is the `Annotated[T, Query()] = <default>` declaration the *Defining Endpoint Parameters* convention already requires: it makes the direct-call default the real value, so a test can omit the param and still exercise the default. Pass the parameter explicitly (e.g., `isTrashed=False`) only for params still on the legacy `Query(default=...)` shape; `get_asset_statistics` is the canonical case. A test that omits the param is the only one that pins the default — writing it against the legacy shape silently asserts the wrong branch.
- Do not add `__init__.py` to test directories — the project uses pytest's rootdir-based import resolution. Adding `__init__.py` switches pytest to package-based imports, breaking test discovery. A corollary: test-module **basenames must be unique across the whole tree**, so an HTTP-level `TestClient` test can't reuse a unit test's name (`tests/unit/api/test_jobs.py` → `tests/integration/test_jobs_integration.py`); collisions fail collection with `import file mismatch`. Suffix the integration file with `_integration`, mirroring `test_oauth_integration.py`.
- When code under test sleeps on a module-level delay/timeout constant (e.g., `_VIDEO_EMIT_DELAY_SECONDS` in `routers/api/assets.py`), **every** test that exercises the delayed path must patch the constant to a near-zero value (typically `0.0`) — not just the test that explicitly asserts on the deferral. Tests that only touch the delayed path incidentally (drains, end-of-test cleanup, error-path coverage) silently wait the real delay otherwise, ballooning suite runtime. Use `patch("module.path._CONSTANT_NAME", 0.0)` inside the same `with` block as the other mocks so the patch covers the spawned task's lifetime. When adding a new delay constant, grep tests for every call site that reaches it and audit each test for an explicit patch — `tests/unit/api/test_assets.py::test_upload_regular_video_proceeds` and `test_video_upload_defers_websocket_events` are the canonical pattern.
